# Unity Target vs OpenArm Actual - 追蹤延遲分析

## 問題描述

機械臂實際位置（OpenArm Actual）跟不上 Unity 發送的目標位置（Unity Target），無法順暢動作。

從 `right_all_joints_20260120_152921.jpg` 圖表觀察到的平均誤差：

| 關節 | 平均誤差 (rad) | 平均誤差 (度) |
|------|----------------|---------------|
| Joint 1 | 0.2114 | ~12° |
| Joint 2 | 0.0790 | ~4.5° |
| Joint 3 | 0.1231 | ~7° |
| Joint 4 | 0.1404 | ~8° |
| Joint 5 | 0.1409 | ~8° |
| Joint 6 | 0.0562 | ~3° |
| Joint 7 | 0.1793 | ~10° |

---

## 原因分析

### 1. Ruckig 軌跡平滑參數限制（主要原因）

**位置**：`unity_interface_follower.py` 第 146-152 行

```python
# 最大速度 (rad/s)
RUCKIG_MAX_VELOCITY = [1.2, 1.2, 1.5, 1.5, 2.0, 2.0, 2.0]
# 最大加速度 (rad/s²)
RUCKIG_MAX_ACCELERATION = [8.0, 8.0, 12.0, 12.0, 15.0, 15.0, 15.0]
# 最大 jerk (rad/s³)
RUCKIG_MAX_JERK = [40.0, 40.0, 60.0, 60.0, 80.0, 80.0, 80.0]
```

**影響**：
- Ruckig 會將 Unity 傳來的目標位置進行「平滑處理」
- 當目標變化太快時，Ruckig 會故意讓機械臂慢下來
- 這是為了避免劇烈動作，但會導致追蹤滯後

**從圖表可見**：在快速變化的區段（如 Joint 3 在 ~25-30s），實際位置明顯滯後於目標。

---

### 2. MIT 控制 Kp/Kd 參數偏低

**位置**：`unity_interface_follower.py` 第 105-108 行

```python
KP = [30.0, 30.0, 20.0, 20.0, 5.0, 5.0, 5.0]
KD = [2.75, 2.5, 0.7, 0.4, 0.7, 0.6, 0.5]
```

**影響**：
- MIT 控制公式：`τ = Kp * (target - actual) + Kd * (target_vel - actual_vel) + τ_ff`
- Kp 越低，位置誤差需要越大才能產生足夠的力矩來追蹤
- Joint 5-7（手腕小馬達 DM4310）的 Kp=5 非常低，追蹤會很慢

**馬達對應**：
| 關節 | 馬達型號 | Kp | Kd |
|------|----------|-----|-----|
| Joint 1-2 | DM8009 | 30.0 | 2.75/2.5 |
| Joint 3-4 | DM4340 | 20.0 | 0.7/0.4 |
| Joint 5-7 | DM4310 | 5.0 | 0.7/0.6/0.5 |

---

### 3. 速度限制設定

**位置**：`unity_interface_follower.py` 第 125 行

```python
MAX_POSITION_RATE = [1.2, 1.2, 1.5, 1.5, 2.0, 2.0, 2.0]  # rad/s
```

**影響**：
- Joint 1-2：最大 1.2 rad/s ≈ 69°/s
- Joint 3-4：最大 1.5 rad/s ≈ 86°/s
- Joint 5-7：最大 2.0 rad/s ≈ 115°/s

如果 Unity 端手臂揮動速度超過這個限制，機械臂就會跟不上。

---

## 影響程度總結

| 因素 | 說明 | 影響程度 |
|------|------|----------|
| **Ruckig 平滑** | 故意讓動作平滑，限制速度/加速度/jerk | ⭐⭐⭐ 最大 |
| **Kp 參數偏低** | 需要較大誤差才能產生足夠力矩 | ⭐⭐ 中等 |
| **速度限制** | 限制最大移動速度 | ⭐⭐ 中等 |

---

## 改善建議

### 方案 A：提高 Ruckig 限制（推薦先試，風險最低）

```python
# 提高速度限制（約 1.5-2 倍）
RUCKIG_MAX_VELOCITY = [2.0, 2.0, 2.5, 2.5, 3.0, 3.0, 3.0]
# 提高加速度限制
RUCKIG_MAX_ACCELERATION = [15.0, 15.0, 20.0, 20.0, 25.0, 25.0, 25.0]
# 提高 jerk 限制
RUCKIG_MAX_JERK = [80.0, 80.0, 100.0, 100.0, 150.0, 150.0, 150.0]
```

**優點**：保持平滑動作，減少抖動風險
**缺點**：仍有一定延遲

---

### 方案 B：提高 Kp（小心調整，可能震盪）

```python
# 提高 Kp（約 1.5 倍）
KP = [45.0, 45.0, 30.0, 30.0, 8.0, 8.0, 8.0]
```

**優點**：追蹤更快速
**缺點**：Kp 過高可能導致震盪或抖動

---

### 方案 C：關閉 Ruckig 平滑（直接追蹤）

```python
USE_RUCKIG_SMOOTHING = False  # 第 144 行
```

**優點**：最直接的追蹤，延遲最小
**缺點**：動作可能不平滑，有抖動風險

---

### 方案 D：組合調整（進階）

同時調整 Ruckig 參數和 Kp：

```python
# Ruckig 參數（適度提高）
RUCKIG_MAX_VELOCITY = [1.8, 1.8, 2.2, 2.2, 2.8, 2.8, 2.8]
RUCKIG_MAX_ACCELERATION = [12.0, 12.0, 16.0, 16.0, 20.0, 20.0, 20.0]
RUCKIG_MAX_JERK = [60.0, 60.0, 80.0, 80.0, 100.0, 100.0, 100.0]

# Kp 參數（適度提高）
KP = [40.0, 40.0, 25.0, 25.0, 7.0, 7.0, 7.0]
```

## MIT 控制參數設定指南

### 參數範圍

| 參數 | 範圍 | 說明 |
|------|------|------|
| Kp | 0 ~ 500 | 位置增益（剛度） |
| Kd | 0 ~ 5 | 速度阻尼 |
| P_MAX | 預設 12.5 rad | 位置映射範圍 |
| V_MAX | 依馬達型號 | 速度映射範圍 |
| T_MAX | 依馬達型號 | 扭矩映射範圍 |

### 常見參數設定範例

根據達妙官方文件和社群經驗：

| 應用場景 | Kp | Kd | 說明 |
|----------|-----|-----|------|
| **一般位置控制** | 50 | 1.0 | 標準追蹤，平衡響應與穩定 |
| **快速響應** | 80~100 | 0.5~1.0 | 追蹤更快，但可能抖動 |
| **柔順控制** | 10~30 | 2.0~3.0 | 適合人機互動，較軟 |
| **高精度定位** | 100~150 | 1.5~2.0 | 需要高剛度場景 |

### 官方建議值（Seeed Studio Wiki）

- **Kp**: 2~10 N·m/rad（較保守）
- **Kd**: ~1 N·m·s/rad

### GitHub 社群常用值

```python
# DM4310 常用設定
kp = 50.0
kd = 0.3

# 位置-速度控制
p_des = 1.57      # 目標角度 90°
v_des = 5.0       # 最大速度 5 rad/s
kp = 50.0         # 位置增益
kd = 1.0          # 速度阻尼
t_ff = 0.0        # 前饋力矩
```

### 重要注意事項

1. **Kd 不能為 0**：位置控制時若 Kd=0，會導致震盪甚至失控
2. **阻尼係數**：調試助手自動計算時，阻尼係數通常設為 2.0~10.0
3. **逐步調整**：建議從較低的 Kp 開始，逐步提高觀察響應
